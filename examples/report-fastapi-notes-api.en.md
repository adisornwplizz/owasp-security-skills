## 1. Executive summary

**Overall risk: Critical** — **No-go for the beta as it stands.** Anyone on the internet can forge a login token (F-001), and with it read every user's notes (F-003, F-005), list every user's email (F-004) and run code on the server (F-006, F-007).

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 8 | 6 | 5 | 3 | 2 |

**Fix first:**
1. F-001, F-002, F-013 — Rewrite token handling in `app/security.py`: verify the signature with HS256 only, require `exp`, and load a new random key from the environment (the committed one is burned).
2. F-006, F-007, F-009 — Remove the pickle/YAML import path, the `shell=True` PDF export and the open `/avatar` fetch, or replace them with the fixed versions below.
3. F-003, F-004, F-005, F-008 — Scope every note query to the caller, parameterize search, add a server-side admin check and verify billing-webhook signatures; add a two-user test per route.

Also before launch: switch to Argon2 and reset passwords, and stop logging passwords (F-010, F-011).

## 3. Findings

Severity = Likelihood × Impact (OWASP Risk Rating). Because of F-001 anyone can mint a token, so every "logged-in only" route is effectively reachable by anyone on the internet until F-001/F-002 are fixed. Ratings below assume F-001 is fixed (i.e. "any beta user"); they would not go down otherwise.

### F-001 · Login tokens are never verified: anyone can act as any user or admin — Critical
- **Category:** A04:2025 Cryptographic Failures · API2:2023 Broken Authentication · CWE-347 (tag A07:2025)
- **Location:** `app/security.py:20` · **Confidence:** Confirmed (PyJWT 1.7.1 honours `verify_signature: False`) · **L×I:** H×H — unauthenticated, one crafted header; full takeover of any account including admin
- **Evidence:**
  ```python
  token = authorization.split(" ")[-1]
  data = jwt.decode(token, SECRET_KEY, algorithms=["HS256", "none"], options={"verify_signature": False})
  return {"id": data["sub"], "admin": data.get("admin", False)}
  ```
- **Impact:** The server trusts whatever `sub` and `admin` a caller puts in the token body. Anyone on the internet can read, import and delete any user's notes and reach every "logged-in" route below, with no password.
- **Fix:** (PyJWT 2.x, see F-017; `sub` must be a string from PyJWT 2.10)
  ```python
  from datetime import datetime, timedelta, timezone
  def create_token(user_id: int, is_admin: bool) -> str:
      now = datetime.now(timezone.utc)
      return jwt.encode({"sub": str(user_id), "admin": is_admin, "iat": now,
                         "exp": now + timedelta(hours=1), "iss": "notes-api"},
                        SECRET_KEY, algorithm="HS256")          # 2.x returns str: drop .decode()

  def current_user(authorization: str = Header(None)):
      scheme, _, token = (authorization or "").partition(" ")
      if scheme.lower() != "bearer" or not token:
          raise HTTPException(status_code=401)
      try:
          data = jwt.decode(token, SECRET_KEY, algorithms=["HS256"], issuer="notes-api",
                            options={"require": ["exp", "iat", "sub", "iss"]})
          return {"id": int(data["sub"]), "admin": bool(data.get("admin", False))}
      except (jwt.PyJWTError, ValueError):
          raise HTTPException(status_code=401)
  ```
- **Verify:** test: a token signed with a different key → 401; an unsigned token (`alg` none) → 401; an expired token → 401; a fresh login token → 200 on `GET /notes`.

### F-002 · JWT signing key is a hard-coded placeholder committed to git — Critical
- **Category:** A07:2025 Authentication Failures · API2:2023 · CWE-798, CWE-321 (tag A04:2025)
- **Location:** `app/settings.py:1` (used at `app/security.py:12,20`) · **Confidence:** Confirmed · **L×I:** H×H — live signing key in the repo, no env override, short dictionary-style value; impact is token forgery for any user
- **Evidence:**
  ```python
  SECRET_KEY = "dev-****"      # HS256 key, 20 chars, placeholder-style (redacted)
  ```
- **Impact:** Even after F-001 is fixed, anyone who has seen the repo, or who cracks this short key offline from any one issued token, can sign valid admin tokens. The value is in git history, so treat it as burned.
- **Fix:**
  ```python
  # app/settings.py
  import os
  SECRET_KEY = os.environ["JWT_SECRET"]   # python -c "import secrets; print(secrets.token_urlsafe(48))"
  if len(SECRET_KEY) < 32:
      raise RuntimeError("JWT_SECRET must be >= 32 random characters")
  ```
  Store it in your host's secret store, never in the repo. Changing it invalidates all existing tokens, which is what you want.
- **Verify:** app refuses to start without `JWT_SECRET`; `git grep -n "SECRET_KEY = \""` returns nothing.

### F-003 · Any user can read any other user's note by ID (BOLA/IDOR) — Critical
- **Category:** A01:2025 Broken Access Control · API1:2023 BOLA · CWE-639
- **Location:** `app/main.py:55` (+1 similar: `export_pdf`, `app/main.py:87-88` never checks who owns `note_id`) · **Confidence:** Confirmed · **L×I:** H×H — any beta user, sequential integer IDs; other users' private notes
- **Evidence:**
  ```python
  @app.get("/notes/{note_id}")
  def get_note(note_id: int, user=Depends(current_user)):
      conn = get_conn()
      row = conn.execute("SELECT * FROM notes WHERE id = ?", (note_id,)).fetchone()
  ```
- **Impact:** This is exactly the "people seeing each other's notes" case. Note IDs are SQLite integers, so a beta user can step through 1, 2, 3… and read every note in the database.
- **Fix:** one owner-scoped lookup, reused by `get_note` and `export_pdf`:
  ```python
  def get_owned_note(conn, note_id: int, user_id: int):
      row = conn.execute("SELECT id, title, body FROM notes WHERE id = ? AND owner_id = ?",
                         (note_id, user_id)).fetchone()     # list columns explicitly; adjust to your schema
      if not row:
          raise HTTPException(status_code=404)              # same answer for "missing" and "not yours"
      return row
  ```
- **Verify:** test with two users: B's token → `GET /notes/{A's note id}` returns 404; A's token returns 200. Same for `POST /notes/{id}/export-pdf`.

### F-004 · `/admin/stats` has no admin check: any user gets every user's email — Critical
- **Category:** A01:2025 Broken Access Control · API5:2023 BFLA · CWE-862
- **Location:** `app/main.py:108-111` · **Confidence:** Confirmed · **L×I:** H×H — any beta user; bulk PII (username + email of all users)
- **Evidence:**
  ```python
  @app.get("/admin/stats")
  def admin_stats(user=Depends(current_user)):
      users = conn.execute("SELECT id, username, email, plan FROM users").fetchall()
  ```
- **Impact:** Any of the 200 beta users can download the full user list with email addresses. The token carries an `admin` claim, but nothing reads it.

  ```python
      if not row or not row["is_admin"]:
          raise HTTPException(status_code=403)
      return user

  @app.get("/admin/stats")
  def admin_stats(user=Depends(require_admin)): ...
  ```
- **Verify:** non-admin token → `GET /admin/stats` returns 403; admin token → 200.

### F-005 · SQL injection in note search exposes the whole database — Critical
- **Category:** A05:2025 Injection · CWE-89
- **Location:** `app/main.py:48` · **Confidence:** Confirmed · **L×I:** H×H — any beta user, one query parameter; read access to every table
- **Evidence:**
  ```python
  rows = conn.execute(f"SELECT * FROM notes WHERE owner_id = {user['id']} AND body LIKE '%{q}%'").fetchall()
  ```
- **Impact:** A `q` value containing a quote character ends the string literal and the rest is parsed as SQL, so the caller can read any table: all users' notes and the `users` table with password hashes (unsalted SHA-1, F-010). The token's `sub` is interpolated too, and is attacker-chosen while F-001 exists. `sqlite3` runs one statement per call, so this is a full read, not stacked writes.
- **Fix:**
  ```python
  from fastapi import Query
  @app.get("/notes/search")
  def search(q: str = Query(..., min_length=1, max_length=200), user=Depends(current_user)):
      like = "%" + q.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_") + "%"
      rows = get_conn().execute(
          "SELECT id, title, body FROM notes WHERE owner_id = ? AND body LIKE ? ESCAPE '\\' LIMIT 100",
          (user["id"], like)).fetchall()
      return [dict(r) for r in rows]
  ```
- **Verify:** test: `q` containing a single quote returns 200 with only the caller's matching notes (no 500); `rg -n 'execute\(f"' app` returns nothing.

### F-006 · Note import unpickles / YAML-loads the request body: remote code execution — Critical
- **Category:** A08:2025 Software or Data Integrity Failures · CWE-502
- **Location:** `app/main.py:76` (pickle) and `app/main.py:78` (`yaml.Loader`) · **Confidence:** Confirmed · **L×I:** H×H — any beta user (anyone while F-001 exists); RCE
- **Evidence:**
  ```python
  raw = await request.body()
  if request.headers.get("content-type") == "application/x-python-pickle":
      notes = pickle.loads(base64.b64decode(raw))
  else:
      notes = yaml.load(raw, Loader=yaml.Loader)
  ```
- **Impact:** Both branches let the request body build arbitrary Python objects. A crafted body in either format runs code as the API process: full server takeover, including the DB file and the signing key.
- **Fix:** accept plain JSON validated by a schema (drop pickle entirely):
  ```python
  class NoteIn(BaseModel):
      title: str = Field(..., max_length=200)
      body: str = Field(..., max_length=100_000)

  @app.post("/notes/import")
  def import_notes(notes: List[NoteIn], user=Depends(current_user)):
      if len(notes) > 500:
          raise HTTPException(status_code=413, detail="max 500 notes per import")
      conn = get_conn()
      with conn:  # single transaction
          conn.executemany("INSERT INTO notes(owner_id, title, body) VALUES (?,?,?)",
                           [(user["id"], n.title, n.body) for n in notes])
      return {"imported": len(notes)}
  ```
  If YAML import is a real requirement, use `yaml.safe_load(raw)` and validate each item with `NoteIn`.
- **Verify:** test: a request with the pickle content type gets 422 and never reaches a deserializer; `rg -n "pickle|yaml\.load\(" app` returns nothing.

### F-007 · PDF export builds a shell command from the `filename` parameter: remote code execution — Critical
- **Category:** A05:2025 Injection · CWE-78 (+ CWE-22 path traversal, CWE-377 shared `/tmp`)
- **Location:** `app/main.py:88` · **Confidence:** Confirmed · **L×I:** H×H — any beta user, one query parameter; RCE
- **Evidence:**
  ```python
  def export_pdf(note_id: int, filename: str, user=Depends(current_user)):
      subprocess.run(f"wkhtmltopdf /tmp/note-{note_id}.html /tmp/{filename}.pdf", shell=True, check=True)
      return {"file": f"/tmp/{filename}.pdf"}
  ```
- **Impact:** `filename` is pasted into a `/bin/sh` command line, so a value with shell metacharacters runs extra commands on the server. A value with `../` writes the PDF anywhere the process can write. The route also skips the ownership check (F-003) and leaks server paths.
- **Fix:** no shell, no user-chosen server path, owner-scoped note. Note that nothing in this repo creates `/tmp/note-*.html`, so if the feature is unfinished, the simplest fix before the beta is to remove the route.
  ```python
  @app.post("/notes/{note_id}/export-pdf")
  def export_pdf(note_id: int, user=Depends(current_user)):
      note = get_owned_note(get_conn(), note_id, user["id"])                 # F-003
      with tempfile.TemporaryDirectory() as d:
          src, out = f"{d}/note.html", f"{d}/note.pdf"
          with open(src, "w") as f:
              f.write(f"<h1>{html.escape(note['title'])}</h1><pre>{html.escape(note['body'])}</pre>")
          subprocess.run(["wkhtmltopdf", "--disable-local-file-access", "--disable-javascript", src, out],
                         check=True, timeout=30)                              # argv list, no shell
          return Response(open(out, "rb").read(), media_type="application/pdf")
  ```
- **Verify:** unit test with `subprocess.run` mocked asserts it gets a list and no `shell=True`; `rg -n "shell=True" app` returns nothing.

### F-008 · Billing webhook accepts unsigned requests: anyone can upgrade any account to "pro" — Critical
- **Category:** A08:2025 Software or Data Integrity Failures · API10:2023 Unsafe Consumption of APIs · CWE-345 (+ CWE-306)
- **Location:** `app/main.py:98-104` · **Confidence:** Confirmed · **L×I:** H×H — unauthenticated, one request; payment abuse
- **Evidence:**
  ```python
  @app.post("/webhooks/billing")
  async def billing_webhook(request: Request):
      event = await request.json()
      if event.get("type") == "subscription.paid":
          conn.execute("UPDATE users SET plan = 'pro' WHERE id = ?", (event["data"]["user_id"],))
  ```
- **Impact:** No login and no signature check. Anyone who finds the URL can post a "subscription.paid" event for any user ID and get the paid plan without paying, or grant it to every user.
- **Fix:** verify the provider's signature over the raw body before parsing. Prefer the provider SDK (e.g. Stripe `stripe.Webhook.construct_event(raw, sig_header, secret)`, which also enforces a timestamp window). Generic shape:
  ```python
  WEBHOOK_SECRET = os.environ["BILLING_WEBHOOK_SECRET"].encode()
  raw = await request.body()
  sent = request.headers.get("X-Signature", "")               # header name/format: see provider docs
  expected = hmac.new(WEBHOOK_SECRET, raw, hashlib.sha256).hexdigest()
  if not hmac.compare_digest(sent, expected):
      log.warning("billing webhook rejected: bad signature")
      raise HTTPException(status_code=401)
  event = json.loads(raw)   # then: skip already-seen event IDs; map provider customer ID -> user in your DB
  ```
- **Verify:** test: unsigned or wrongly signed POST → 401 and `users.plan` unchanged; correctly signed → 200.

### F-009 · `/avatar` fetches any URL from the server (SSRF) — High
- **Category:** A01:2025 Broken Access Control · API7:2023 SSRF · CWE-918
- **Location:** `app/main.py:94` · **Confidence:** Confirmed · **L×I:** H×M — any beta user; semi-blind (size, type and timing come back), impact depends on what your host can reach (cloud metadata without IMDSv2 raises it)
- **Evidence:**
  ```python
  r = requests.get(url, verify=False, timeout=None)
  return {"size": len(r.content), "type": r.headers.get("content-type")}
  ```
- **Impact:** Users can make the server send requests to localhost, the private network or the cloud metadata address and map what answers. Redirects are followed, so checking only the first host is not enough. Nothing is stored, so the feature looks unfinished: removing it is the cheapest fix.
- **Fix:** (if kept) allowlist hosts, no redirects, timeout and size cap:
  ```python
  AVATAR_HOSTS = {"www.gravatar.com"}                      # your real avatar sources
  u = urllib.parse.urlsplit(url)
  if u.scheme != "https" or u.hostname not in AVATAR_HOSTS:
      raise HTTPException(status_code=400, detail="unsupported avatar host")
  r = requests.get(url, timeout=(3, 5), allow_redirects=False, stream=True)   # verify stays on
  data = r.raw.read(2_000_001, decode_content=True)        # reject if len(data) > 2_000_000
  ```
- **Verify:** test with `requests.get` mocked: loopback, link-local and `http://` URLs → 400 and the mock is never called.

### F-010 · Passwords stored as unsalted SHA-1 — High
- **Category:** A04:2025 Cryptographic Failures · API2:2023 · CWE-916, CWE-759
- **Location:** `app/security.py:8` (compared at `app/main.py:33`) · **Confidence:** Confirmed · **L×I:** M×H — needs a DB read (F-005 provides one, as would a leaked backup); all users' passwords
- **Evidence:** `return hashlib.sha1(pw.encode()).hexdigest()`
- **Impact:** SHA-1 is fast and unsalted, so a leaked `users` table gives up most passwords within hours on one GPU, and users who share a password share a hash. Beta users reuse passwords on other sites.
- **Fix:** `pip install argon2-cffi`; defaults are argon2id above the OWASP minimum.
  ```python
  ph = PasswordHasher()
  def hash_password(pw: str) -> str: return ph.hash(pw)
  def verify_password(stored: str, pw: str) -> bool:
      try: return ph.verify(stored, pw)
      except (VerificationError, InvalidHashError): return False
  ```
  Existing rows: reset passwords before the beta opens (simplest), or store `ph.hash(old_sha1)` now and replace it with `ph.hash(password)` at the next successful login.
- **Verify:** stored hashes start with `$argon2id$`; login test with correct password → 200, wrong → 401.

### F-011 · Every login writes the user's password to the log in clear text — High
- **Category:** A09:2025 Security Logging & Alerting Failures · CWE-532 (+ CWE-117 log forging)
- **Location:** `app/main.py:30` · **Confidence:** Confirmed · **L×I:** M×H — needs log access; every user's password. Critical if stdout is shipped to a hosted log service.
- **Evidence:** `log.info(f"login username={body.username} password={body.password}")`
- **Impact:** Anyone who can read logs (hosting dashboard, log vendor, a teammate) gets working credentials, including wrong-password attempts that are often a user's other passwords. Raw `username` also lets a caller inject fake log lines.
- **Fix:** `log.info("login attempt user=%r", body.username)` (never the password; `%r` escapes newlines). If this has run anywhere with real accounts, delete those logs and treat the passwords as exposed.
- **Verify:** pytest `caplog`: after a login call the password string appears in no log record.

### F-012 · Debug mode is on in the only config: stack traces go to unauthenticated callers — High
- **Category:** A02:2025 Security Misconfiguration · API8:2023 · CWE-489
- **Location:** `app/settings.py:3`, `app/main.py:19` (+ `README.md:2` runs `uvicorn --reload`) · **Confidence:** Confirmed · **L×I:** H×M — unauthenticated, trivial (e.g. a non-JSON body to `/webhooks/billing`); exposes source paths and code lines such as the F-005 query
- **Evidence:** `DEBUG = True` → `app = FastAPI(debug=DEBUG, title="notes-api")`
- **Impact:** With `debug=True`, Starlette answers every unhandled error with the full Python traceback, which helps an attacker tune F-005/F-007. `--reload` is a dev file-watcher.
- **Fix:** `DEBUG = os.environ.get("APP_DEBUG") == "1"` (off by default); run prod as `uvicorn app.main:app --workers 2` (no `--reload`). Then fix F-015, which takes over once debug is off.
- **Verify:** with no env set, a malformed webhook body gets a response with no "Traceback" text.

### F-013 · Tokens never expire and cannot be revoked — High
- **Category:** A07:2025 Authentication Failures · API2:2023 · CWE-613
- **Location:** `app/security.py:12` · **Confidence:** Confirmed · **L×I:** M×H — needs one leaked token; permanent account access, and a stale `admin: true` survives demotion
- **Evidence:** `jwt.encode({"sub": user_id, "admin": is_admin}, SECRET_KEY, algorithm="HS256")` (no `exp`/`iat`)
- **Impact:** A token copied once (logs, screenshot, shared device) works forever; there is no logout.
- **Fix:** the F-001 code adds a 1-hour `exp` and requires it. For logout and password change, add `users.token_version`, put it in the token as `ver`, compare it in `current_user`, and bump it to revoke.
- **Verify:** tokens without `exp` or with `exp` in the past → 401; after bumping `token_version` the old token → 401.

### F-014 · No limits on page size, import size or outbound wait: one user can stall the API — High
- **Category:** A06:2025 Insecure Design · API4:2023 Unrestricted Resource Consumption · CWE-770, CWE-400
- **Location:** `app/main.py:39` (+2 similar: `app/main.py:74` unbounded body, `app/main.py:94` `timeout=None`) · **Confidence:** Confirmed · **L×I:** H×M — any beta user; service-wide DoS
- **Evidence:**
  ```python
  def list_notes(page_size: int = 100000, user=Depends(current_user)):   # no cap; negative = unlimited in SQLite
  raw = await request.body()                                             # whole body in memory, no size limit
  r = requests.get(url, verify=False, timeout=None)                      # waits forever
  ```
- **Impact:** Sync routes share a small thread pool, so a few dozen `/avatar` calls to a URL that never answers freeze every route; large imports exhaust memory.
- **Fix:** `page_size: int = Query(50, ge=1, le=200)`; cap body size at the proxy (e.g. nginx `client_max_body_size 1m`) plus the 500-item cap in F-006; timeouts and size cap from F-009; per-user rate limits (slowapi) on import, export and avatar.
- **Verify:** `GET /notes?page_size=100000` → 422; with a mocked hanging upstream, `/avatar` returns within ~8 s.
